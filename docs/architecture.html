Component index and connections

  1. Busy text

    The active session receives plain text while queue mode is enabled. The optional router gets a chance to handle it before the adapter buffers the text.

    tests/test_router_lifecycle.py

    Leads to Admission

  2. Admission

    The optional router checks waiting work, mode, context, and both capacity limits. With routing off or admission declined, ordinary text continues to the adapter.

    patches/apply_busy_overflow_router_patch.py

    Leads to Debounce or Acknowledgment

  3. Debounce

    The adapter collects a burst for 0.35 seconds, up to a one-second hard cap, then the patch hands it to the FIFO when the runner and source match.

    patches/apply_debounce_fifo_patch.py

    Leads to FIFO or Pending slot

  4. FIFO

    Accepted bursts get separate turns in arrival order. A different sender is offered a separate turn to preserve the message boundary.

    tests/test_debounce_flush.py

    End of this path

  5. Pending slot

    A same-sender photo caption can merge into the pending event. A same-sender text burst can also use the historical merge when the FIFO refuses it at its cap.

    docs/CASE_STUDY.md

    End of this path

  6. Acknowledgment

    One owned task sends the acknowledgment with a five-second deadline. A failed send or a timeout can still proceed to generation.

    tests/test_router_lifecycle.py

    Leads to Generation

  7. Generation

    The accepted prompt runs once. After an acknowledgment timeout, the owner waits for remaining acknowledgment cleanup before it can release the slot.

    patches/apply_busy_overflow_router_patch.py

    Leads to Slot released

  8. Slot released

    The completion callback removes the owner from the registries. An acknowledgment that never finishes cleanup can keep the slot occupied.

    tests/test_router_lifecycle.py

    End of this path
Worked routing scenarios

  1. First follow-up

    With both patches present, nothing is waiting yet. The router declines, the adapter flushes the burst, and an available FIFO accepts it.

    Busy text → Admission → Debounce → FIFO

  2. Independent overflow

    A self-contained question arrives behind waiting work. In independent mode with capacity available, a timely acknowledgment precedes generation and slot release.

    Busy text → Admission → Acknowledgment → Generation → Slot released

  3. Caption fallback

    With routing off, same-sender busy text joins a pending photo as a caption when the adapter flushes it.

    Busy text → Admission → Debounce → Pending slot

  4. Slow acknowledgment

    For an admitted prompt, the owner requests cancellation after five seconds and starts generation. The slot returns only when both generation and acknowledgment cleanup finish.

    Busy text → Admission → Acknowledgment → Generation → Slot released
